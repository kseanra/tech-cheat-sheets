Docker: container name already in use

What "Conflict. The container name is already in use" means, and the fastest way to get unstuck.

The error

You ran docker run --name web ... and Docker refused, with something like:

docker: Error response from daemon: Conflict. The container name "/web" is already
in use by container "8f3a2c1e9b4d". You have to remove (or rename) that container
to be able to reuse that name.

Why it happens

Container names in Docker must be unique on the host. When you stop a container with docker stop, the container isn't deleted — it just moves to the "Exited" state. It still holds on to its name (and its filesystem, logs, and exit code) until you explicitly remove it. So the next time you try to docker run a new container with that same --name, Docker sees the name is still claimed and refuses to start a duplicate.

This is especially common when a container crashes or you re-run a start script without cleaning up first — the old, stopped container is still sitting there.

Fix it

First, check what's holding the name (including stopped containers):

docker ps -a --filter "name=web"

If it's stopped, just remove it, then re-run your original command:

docker rm web

If it's still running and you want to replace it, force-remove it (this stops it first):

docker rm -f web

If you'd rather keep the old container around, give it a different name instead of removing it, or rename the existing one out of the way:

docker rename web web-old
docker run --name web ...

Prevent it next time

For throwaway or short-lived containers — tests, one-off scripts, debugging sessions — add --rm so Docker automatically deletes the container (and frees its name) the moment it exits:

docker run --rm --name web ...

For long-running services you manage with a script, have the script remove any existing container with the same name before starting a new one, e.g. docker rm -f web 2>/dev/null; docker run --name web ..., or better, use Docker Compose so container lifecycle is handled for you.
