Git: fatal: not a git repository

What this means, why Git can't find a repo here, and how to fix or recover it.

The error

You ran a git command — git status, git log, git add, whatever — and got:

fatal: not a git repository (or any of the parent directories): .git

Why it happens

Git commands work by walking up from your current directory looking for a .git folder — the hidden directory that actually stores the repository's history, objects, and refs. This error means Git walked all the way up to the filesystem root without finding one. Usually that's because:

  • You're in a plain folder that was never initialized with git init or cloned with git clone.
  • You cd'd into the wrong directory — a sibling folder, or one level above/below the actual repo.
  • The .git folder inside your project got deleted, moved, or corrupted (accidentally, by a cleanup script, or by a bad merge tool).

Fix it

First, confirm where you actually are and what's around you:

pwd
ls -la

If you can see a .git folder in a nearby directory (parent, sibling, or subfolder), just cd into the correct one:

cd /path/to/the/actual/repo
git status

If this is genuinely a new project and you meant to start tracking it with Git for the first time, initialize a repository here:

git init

If .git used to exist in this exact folder and is now gone, a bare git init only creates an empty repository — it does not recover your previous commit history, branches, or remotes. In that case your best option is usually to re-clone from the remote (GitHub, GitLab, etc.) if one exists:

git clone <remote-url> .

If there's no remote and no backup, the history is likely unrecoverable — check any local backups, IDE local history, or CI artifacts that might still hold a copy.

Related: checking where you are

To quickly confirm you're inside a Git working tree (and see its actual root, in case of nested folders), run:

git rev-parse --show-toplevel

If that also fails with the same "not a git repository" error, you've confirmed there is no .git anywhere above your current directory — go straight to the "Fix it" section above.
